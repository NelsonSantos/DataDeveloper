## Summary
- refactor: Consolidates the SQL parsing architecture into DataDeveloper.Antlr and removes the mixed parser ownership model across the solution. This also replaces several fragile regex/string-based SQL analyzers with token-based implementations while preserving current behavior.
- The previous structure split grammars, generated sources, linked source files and parser consumers across multiple projects. That made the build and ownership model inconsistent and kept critical SQL behaviors exposed to regressions from manual heuristics.
- centralizes grammars, checked-in generated parser sources and support files in DataDeveloper.Antlr
- removes linked parser source includes and parser duplication under DataDeveloper.Data/StatementParser
- moves SqlParameterDetector into DataDeveloper.Data
- refactors ResultSetEditabilityAnalyzer to token-based select-shape analysis
- refactors StatementExecutionClassifier to token-based statement classification and schema refresh target parsing
- refactors SqlCompletionProvider in three parts: aliases/target table, clause/context detection, and CTE column inference
- refactors Oracle-specific StatementSplitter detection away from regex-based checks
- expands SqlTokenFormatter to use real lexers for PostgreSQL, Oracle and SQLite
- adds focused unit coverage for the new parser behavior and formatter coverage for the additional providers
