## Summary
- Add support for editing simple SQL result sets directly in the grid. This branch detects when a SELECT is editable, resolves table/column metadata, tracks row edit state in the grid, and persists changes through provider-aware INSERT, UPDATE, and DELETE commands.
- This enables inline editing for simple single-table query results without incorrectly marking complex queries as editable. The implementation also preserves compatibility across the supported database providers and covers provider-specific regressions around generated/defaulted columns and Oracle metadata/identifier handling.
- Detect editability only for simple single-table select * statements, and block editing when PKs are missing or the query is not safe to edit.
- Resolve provider-specific column metadata including PKs, nullability, autogenerated columns, and default values.
- Generate INSERT, UPDATE, and DELETE SQL with correct quoting and parameter styles for SQL Server, MySQL, PostgreSQL, Oracle, and SQLite.
- Add editable row state management in the grid for clean, new, modified, and deleted rows.
- Integrate editing into TabDataGrid, including add row, delete row, discard changes, submit changes, and editable/read-only status messaging.
- Extend NextGrid to support cell edit request/commit flows, focused-cell changes, and formatting/rendering needed by editable result sets.
- Avoid sending explicit NULL values for columns that should be populated by database defaults/autogenerated behavior.
- Fix Oracle metadata loading and identifier casing/quoting for editable result set operations.
